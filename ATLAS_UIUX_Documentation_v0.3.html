1Purpose & how to use this document

This document accompanies the interactive HTML prototype for the four intelligent-learning features planned for ATLAS. Part 1–5 explain the design for reviewers; appendices A–C specify behaviour for the IT team implementing on 3–14 July.

Every screen below is embedded live from the prototype file — previews always match the latest prototype. Keep both files in the same folder. Click Open interactive ↗ on any preview to explore that screen full-size; the dark ribbon at the top of the prototype switches between screens, and the small grey "Simulate" controls are prototype-only tools for demoing states (they are not product UI).

Visual fidelity note: all colours, typography and components were measured directly from the live product at demo.atlaslearn.ai (2 Jul 2026), so the new features look native to the existing app.

3Screen-by-screen walkthrough

3.1 Dashboard — bento layout REC-03SPC-07SPC-08

The dashboard is reorganised as a bento grid so nothing important sits below the fold: the Recommendation card is the hero tile (2×2), with progress (streak/XP/level), Bites entry points (Daily · Weekly · Scheduled), Skill Check, and the Learning Hub (existing six modules) arranged around it. The recommendation card has six states — single, multiple (ranked by severity, duplicates collapsed), manual assignment (T16, purple), frequency-capped (excess queued), empty (with a self-request entry, T17), and a first-visit onboarding state for brand-new learners. The floating 💬 button opens the ATLAS Assistant — the existing three starter questions are kept so new users learn how to use it; the assistant can also hand off into a Chapter Review.

3.2 Post-test trigger REC-03

After a practice test, missed questions are grouped by skill tag. Three wrong answers sharing "Customer Due Diligence" fire trigger T2; on Continue, a modal offers the Chapter Review at the moment of highest intent. Declining never blocks progress — the offer moves to the dashboard card and the 🔔 notification, where it persists until completed (spec 1.3). A post-assessment check-in nudge also appears here (spec 3.4 touchpoint).

Open interactive ↗

3.3 Chapter Review flow REC-03ENG-04

A four-step full-screen flow using the lesson-player shell: Overview (what triggered it, what it covers, time estimate) → Simplified content (2 pages from the Simplified-preset pipeline, with "Why you missed Qx" callouts tied to the learner's own mistakes) → Mini quiz (3 questions, identical behaviour to the live practice test) → Result. Passing awards XP and clears the card + notification automatically; failing fires T15: retry, re-read, or exit with the recommendation kept. A check-in nudge appears once during content, and another after completion — answering "Not really" escalates to a fresh review (escalation over repetition, spec 3.4).

Open interactive ↗

3.4 Lesson session + engagement nudges ENG-04SPC-08

The three nudge types from spec 3.4 render as one shared bottom-right card component — non-intrusive, dismissible, never blocking the slide: Check-in ("too hard or manageable?" — choosing Simplify regenerates the slide as a simplified preset), Rest & Pause (10-second countdown, auto-dismisses), and Pause & Think (workplace reflection prompt). The ⚡ Bonus Bite pop-up demonstrates SPC-08 interleaving: one quick question from a previously learned topic, mid-course.

Open interactive ↗

3.5 Bites — Daily · Weekly · Skill Check SPC-05/06/08

One quiz shell serves three flows. Daily (3 questions) ends with the Leitner ladder: a correct topic promotes one box (7 → 16 days), a miss demotes to Box 0 (review tomorrow) — making the invisible scheduling algorithm legible to learners. Weekly (10–15 questions; 5 in this demo) and Skill Check (random cross-topic) end with a "Sent to your recommendations" panel instead — wrong answers feed the Recommendation System (SPC-04) and can open a Chapter Review directly. Results always show XP (+5 per correct answer), the streak, and badge progress; a perfect Bite lights up Sharpshooter — NEW!.

3.6 Gamification hub SPC-07

A single page for the reward layer: streak milestones (3 / 7 / 14 / 30 / 100 days with the learner's position marked), the full badge catalogue from spec 3.4.1 grouped as Getting Started, Progression (Bronze/Silver/Gold tiers with progress, e.g. Reviewer 6/15), Mastery, and Breadth & Consistency, and the leaderboard with Organisation / Department / Group tabs. Reached from the "View all →" link on the dashboard progress tile.

3.7 Admin console T16Spec 3.3

Two admin surfaces referenced by the spec: Learner Analytics — assessment results with per-skill gap chips; "Assign review" opens a confirmation and the assignment lands on the learner's dashboard as a T16 recommendation. Gamification Settings — the full opt-out matrix from spec 3.3: per-activity toggles for completion / pass (70%) / perfect score across PALS Course, CBL, Assessments, Bites and Chapter Review.

4How the four features connect

Every path leads to the Chapter Review, and every activity feeds the reward layer:

  • Tests → Recommendation: missed skill-tagged questions (T2/T3) create the dashboard card and post-test offer.
  • Bites → Recommendation: wrong Weekly-Bite and Skill-Check answers queue reviews (SPC-04); Daily Bites drive the Leitner schedule.
  • Nudges → Recommendation: check-ins offer simplification in place, and escalate to a review when struggle persists; the assistant (Learning Buddy) offers a review when a topic is asked repeatedly.
  • Everything → Gamification: completing reviews and Bites earns XP, extends the streak, and advances badges — surfaced on the dashboard, the Bites results, and the hub.
  • Completion closes the loop: finishing a review clears its card and notification; the concept is re-checked on the next assessment (the primary success metric, spec 1.2).

5Open questions for review

  • Should manual (T16) assignments be snoozable like automatic recommendations, or always pinned? (Currently: pinned, no "Later".)
  • The "Why you missed Qx" callouts in review content need confirmation that the pipeline can map feedback to specific missed questions (REC-02/04 dependency).
  • Exact frequency caps for recommendations and nudges are engine-level TBDs — the UI shows the capped/queued behaviour but the numbers need tuning with Daffa.
  • Weekly Bites in the demo uses 5 questions; production should draw 10–15 per spec 2.3.
  • Leaderboard scope: spec lists Organisation / Department / Group — confirm data availability for all three levels at launch.
